# TalentBridgeAI live preview

## Start the development server

On Windows, run `START_TALENTBRIDGEAI.bat` (or `RUN_DJANGO_WINDOWS.bat`). The local manager starts Django at:

- Website: <http://127.0.0.1:8000/>
- Live preview dashboard: <http://127.0.0.1:8000/__dev__/>
- Django Admin: <http://127.0.0.1:8000/admin/>

The local launcher explicitly sets `DJANGO_ENV=development` and `DJANGO_DEBUG=true`, then runs `manage.py runserver` with its standard autoreloader. Python edits restart the Django development process; no manual restart is needed. The preview dashboard shows the server URL/mode, current process start time, Django system-check errors, and CSS/JavaScript source availability.

## What refreshes on save

| Changed files | Preview behavior |
| --- | --- |
| `css/**/*.css` | Local stylesheets are replaced in place after the next status poll; the page stays loaded. |
| `js/**/*.js` | The browser parses the source scripts first, then refreshes the page so valid updates run in normal document order. |
| `pages/**/*.html` or Django templates | The browser refreshes the current page to render the saved template. |
| Django `config/` or `jobs/` Python files | Django autoreloads; open pages reconnect and refresh when the server is back. |
| Images, logos, or videos | The browser refreshes the current page. |

This project has no React/Vue/Vite/webpack frontend build, so component-level HMR is not applicable. CSS can update without a page reload; JavaScript and templates require a reload to reliably recreate the page. JavaScript syntax errors prevent the refresh so the currently running page remains intact. A changed stylesheet is kept in place until its replacement loads; a failed replacement shows a browser notice and preserves the currently displayed stylesheet.

## Errors and recovery

- The dashboard refreshes its status automatically and lists Django system-check and missing-source errors. The monitor polls every five seconds, times out stalled health requests, backs off after failures, and announces a continuous outage once rather than re-announcing each retry. It clears that notice after the first successful recovery poll.
- When Django is restarting or unavailable, the page reports that state and retries. Application tracebacks and autoreload failures are written to `logs/server.log`. The status fingerprint scan prunes `.venv`, `venv`, `__pycache__`, and `staticfiles` directories so installed dependencies are not rescanned on each poll.
- Fix the reported source error and save again. Django's development autoreloader attempts to start the corrected code. It does not roll back arbitrary Python or template edits to an older revision; use source control or a backup to restore a previous version.
- JavaScript runtime errors remain visible in browser developer tools. For Django request exceptions, use the development error page and `logs/server.log`.

## Development versus production

`legacy-django/config/settings.py` requires both `DJANGO_ENV=development` (or `local`) and `DJANGO_DEBUG=true`; the environment defaults to `production`, and DEBUG therefore defaults off. The local Windows manager sets the development variables only for its local process. The preview routes and live-refresh middleware do not activate unless `DEBUG` is true.

For production, use `DJANGO_ENV=production` and `DJANGO_DEBUG=false`, use a production WSGI/ASGI server, and configure production hosts, HTTPS, secrets, database, and static-file delivery. Never expose the local runserver or DEBUG pages to the public internet.

## Static preview

`site/` is generated by `python build_static.py` for static hosting and VS Code Live Server. It is not the Django application; its banner identifies sign-in, Google OAuth, resume uploads, dashboards, and database-backed actions as Django features. A 404 for `/__dev__/state/` on port 5500 is expected because the static preview does not load the Django health monitor. Use port 8000 for those workflows and the development dashboard. Make edits in the source folders listed above, not in generated `site/`.

The generated homepage is `/index.html` on the static preview (port 5500). If `/site/index.html` is opened on Django (port 8000), it redirects to the real Django homepage at `/`.

## Project structure audit

Run `python tools/project_structure_audit.py --check` from the project root to regenerate `PROJECT_STRUCTURE_REPORT.md` and fail on detected missing required entries, syntax errors, broken local imports, missing templates/assets, or missing migrations. Duplicate files and unreferenced assets are reported as review candidates and are never deleted automatically.
